Free KS3 Pixels and Binary Images Cover Lesson: No-Tech + Answers

A complete 60-minute KS3 Computing cover lesson on how computers store pictures in binary. It needs no computers or printing, and includes a supervisor script and full answers.

This is a full one-hour lesson you can leave for cover or pick up with five minutes' notice. Pupils decode binary into pictures, spot a corrupted bit, encode their own image and work out storage sizes. The supervisor does not need any computing knowledge, because everything they need to say or check is below.

Suits: Years 7 to 9, with adjustments near the end. Curriculum link: the KS3 programme of study point on how data of various types, including pictures, can be represented and manipulated digitally in binary. You need: a board, pens, rulers and squared paper or squared exercise books. No printing is required.

Lesson timings

  1. Starter: 5 minutes
  2. Explanation: 8 minutes
  3. Task 1, decode a picture: 10 minutes
  4. Task 2, mystery image and corrupted bit: 7 minutes
  5. Task 3, encode your own image: 12 minutes
  6. Task 4, storage questions: 13 minutes
  7. Plenary: 5 minutes

Key words: pixel, bit, byte (8 bits), resolution, colour depth.

Supervisor script

Starter (5 minutes). Say: "Write down what you think a digital photo is actually made of inside a computer. You have two minutes." Take three answers. Do not correct them yet.

Explanation (8 minutes). Read this out:

"A digital image is a grid of tiny squares called pixels. Computers only store 1s and 0s, and each 1 or 0 is called a bit. In a black and white image, one bit can describe one pixel. Today, 1 means black and 0 means white. The number of pixels in the image is called its resolution. More pixels means more detail, but it also means more data to store."

Then ask pupils to rule an 8 by 8 grid, with each square 1cm wide if possible. Squared paper makes this quick.

Task 1 (10 minutes). Say: "Each row of digits on the board is one row of your grid. Work left to right. Shade the square for a 1 and leave it blank for a 0. Don't guess the picture, follow the code." Pupils then answer in their books: how many black pixels are there, and how many white?

Task 2 (7 minutes). Say: "Rule a second grid and decode the mystery picture." Then write this on the board and read it out: "Task 1's face is perfectly symmetrical. Suppose Row 3 arrived as 10100111. Which bit has been corrupted, and what should it be?"

Task 3 (12 minutes). Say: "On a new 8 by 8 grid, design your own black and white picture. Write the eight rows of binary underneath. Cover your drawing, swap only the binary with a partner, and decode each other's image." Pupils compare the decoded grid with the original. Any difference means an error in the encoding or the decoding, and they should find which row.

Task 4 (13 minutes). Write these questions on the board. Pupils answer in full sentences for 6 and 10, and show working for the rest.

  1. How many pixels are in an 8 by 8 image?
  2. At 1 bit per pixel, how many bits does it need?
  3. How many bytes is that?
  4. How many pixels does a 16 by 16 image have, and how many times more is that than 8 by 8?
  5. How many bytes does a 16 by 16 image need at 1 bit per pixel?
  6. Why would the 16 by 16 version of a face look better?
  7. How many different colours can each pixel have with 2 bits? With 3 bits?
  8. An image uses exactly 5 colours. What is the smallest number of bits needed per pixel, and why?
  9. An image is 100 by 50 pixels and uses 8 bits per pixel. How many bits and how many bytes is that, ignoring any extra file information?
  10. Why don't we save every image at the highest possible resolution and colour depth?

Say before they start: "Size in bits = width × height × bits per pixel. Divide by 8 to get bytes." Write that formula on the board.

Plenary (5 minutes). Each pupil writes one sentence using the words pixel, bit and resolution. Take three aloud. Ask: "If we swapped the rule so 1 meant white, what would happen to the face?" The answer is that it would become a negative, with black and white reversed.

Full answer key

Task 1: a smiling face inside a rounded outline. The two eyes are in Row 3 and the smile is across Rows 5 and 6.

Quick check, black squares per row from Row 1 to Row 8: 4, 2, 4, 2, 4, 4, 2, 4.

Total: 26 black pixels and 38 white pixels (64 altogether).

Task 2: a heart. Black squares per row from Row 1 to Row 8: 4, 8, 8, 8, 6, 4, 2, 0. Total: 40 black and 24 white.

Corrupted bit: the 7th bit from the left. It arrived as 1 and should be 0. The correct row is 10100101, which reads the same forwards and backwards.

Task 3: answers vary. Check that each row has exactly 8 digits and that partners' decoded grids match the originals.

Task 4:

  1. 8 × 8 = 64 pixels
  2. 64 bits
  3. 64 ÷ 8 = 8 bytes
  4. 16 × 16 = 256 pixels, which is 4 times as many
  5. 256 ÷ 8 = 32 bytes
  6. It has a higher resolution. More, smaller pixels show finer detail, so curves look less blocky.
  7. 2 bits gives 4 colours (00, 01, 10, 11). 3 bits gives 8 colours.
  8. 3 bits. Two bits only gives 4 combinations, which is not enough for 5 colours, and 3 bits gives 8.
  9. 100 × 50 × 8 = 40,000 bits. 40,000 ÷ 8 = 5,000 bytes.
  10. Bigger files take up more storage and take longer to send or load. Accept any reasoned answer that links size to storage, speed or the image not needing that much detail.

Extension for fast finishers

Colour decoding. Write on the board: 00 = white, 01 = red, 10 = blue, 11 = black. Ask pupils to decode 00 01 01 11 10 10. The answer is white, red, red, black, blue, blue.

Run-length encoding. Instead of storing every bit, record how many of each value appear in a row. For example, 00111100 becomes "2 zeros, 4 ones, 2 zeros". Ask pupils to write Row 1 of the heart this way. The answer is 1 zero, 2 ones, 2 zeros, 2 ones, 1 zero. Then ask: "Which rows of the heart save the most writing?" Rows 2 to 4 and Row 8 do, because each is a single run.

Adjusting for different years

  • Year 7 or lower-attaining groups: do Tasks 1 and 3 slowly and answer only questions 1 to 4 and 6 of Task 4. Pupils can read each row aloud in pairs, one calling the digits and one shading.
  • Year 9 or higher-attaining groups: skip the starter discussion, make extension work compulsory, and ask them to calculate the size of a 1920 by 1080 image at 24 bits per pixel. The answer is 49,766,400 bits, or 6,220,800 bytes, about 6.2 MB using 1 MB = 1,000,000 bytes and ignoring compression.

Questions pupils may ask

"Why is my picture wrong?" Check whether they started a row from the right, skipped a square or shaded the 0s. Compare their black squares per row with the counts in the answer key to find the first row that is off.

"Do real photos work like this?" The idea is the same, but real photos use many more pixels and more bits per pixel, so each pixel can show a wide range of colours. Many files are also compressed.

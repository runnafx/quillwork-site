How to Show D&D Initiative Order on Stream in OBS (3 Ways)

A step-by-step guide for DMs and actual-play streamers who want turn order on screen in OBS or Streamlabs. It covers a free text-file method, a browser-source method and a checklist you can run before every session.

Viewers who join partway through combat want to know three things: whose turn it is, who's next, and which round it is. If initiative only lives on your DM screen, you end up repeating it out loud. This guide shows three ways to put it on screen in OBS Studio (most steps work the same in Streamlabs Desktop), from a free setup that takes five minutes to a full tracker you can click through.

Before you start: decide what viewers need to see

Keep it short. A tracker that fits on screen usually shows:

  • Name of each creature or player character, in turn order
  • Initiative number (optional, but it helps viewers follow the sort order)
  • Whose turn it is, highlighted
  • Round number
  • Foes marked differently from the party, by color or a symbol

You don't need to show monster HP or AC. Many DMs hide those on purpose. Group identical monsters into one line ("Goblins") so the list doesn't grow past what fits on screen.

Method 1: Free text-file tracker (works on any setup)

This method uses OBS's built-in Text source, which can read from a file. When you edit and save the file, the text on stream updates.

  1. Make a plain text file, for example `initiative.txt`, in a folder you'll remember.
  2. Type your order, one line per combatant. Mark the current turn with a symbol:

``` ROUND 1 > 18 Aria 15 Borin 12 Goblins (foe) 9 Mira ```

  1. In OBS, click + under Sources and add Text (GDI+) on Windows or Text (FreeType 2) on Mac/Linux.
  2. Tick Read from file and pick `initiative.txt`.
  3. Choose a monospaced font (Consolas, Courier New or similar) so the numbers line up. Set the size to about 40–48 for 1080p.
  4. Turn on a background or outline in the source settings so the text stays readable over game footage or a VTT map.
  5. Drag it to a corner where it won't cover faces or the map.

To advance a turn: move the `>` down one line in your text editor and save. The display updates shortly after.

Pros: free, nothing to install, works offline. Cons: you alt-tab to an editor on every turn, there's no automatic sorting, and it looks plain.

Tip: keep the text file open in a small editor window on a second monitor. Advancing a turn then takes one edit and Ctrl+S.

Method 2: Browser-source tracker (clickable, auto-sorted)

A browser source is a small web page that OBS draws as a layer with a transparent background. An HTML tracker can sort initiative for you, highlight the active turn and count rounds. You can also control it from inside OBS without leaving your scene.

Adding a browser source

  1. Under Sources, click + and choose Browser.
  2. Tick Local file and choose the `.html` file. If the tracker takes settings in its address (like `?party=Aria:18,Borin:15`), untick Local file and paste the full `file:///` address into the URL box instead.
  3. Set Width 1920 and Height 1080 if the page is built for a full 1080p canvas, then position it with the transform handles.
  4. Leave the default custom CSS alone unless the page tells you otherwise. The usual default keeps the background transparent.

Controlling it during play

This is the step most guides leave out. A browser source can't hear your keyboard while OBS's main window has focus. To click or press keys on it:

  • OBS Studio: right-click the source and choose Interact. A window opens where you can click names or press keys, and the changes show on stream.
  • Streamlabs Desktop: browser sources have a similar Interact option in the source's right-click menu.

Keep that Interact window open on your second monitor through combat.

Things that catch people out

  • Changing the URL reloads the page. That resets the turn and round to their starting values. Change the party list between encounters, not partway through a round.
  • "Refresh browser when scene becomes active" in the source properties resets the tracker when you switch scenes. Leave it unticked if you cut away to a BRB scene during combat.
  • "Shutdown source when not visible" has the same effect when you hide the source. Leave it unticked too.
  • Fonts: a page that asks for a font you don't have installed falls back to another one, so check how it looks before you go live.

Method 3: Capture your VTT's own tracker

If you play on a virtual tabletop that has a built-in combat tracker, you can show it directly:

  1. Pop the tracker out into its own window if the VTT allows it.
  2. Add a Window Capture source pointed at that window.
  3. Crop it with Alt+drag (Option+drag on Mac) on the source edges.

Pros: no double entry, because your VTT is already the source of truth. Cons: it often shows things you'd rather hide (monster HP, hidden enemies, GM-only notes), it doesn't match your overlay style, and it can be hard to read at stream resolution. Check exactly what's visible before going live.

Comparison at a glance

  • Text file: free, offline, manual. Best if you stream occasionally and want zero setup.
  • Browser source: auto-sort, highlights and round counter, controlled through Interact. Best if combat is a regular part of your stream.
  • VTT capture: no extra data entry. Best if you already run everything in a VTT and are careful about hidden information.

Fill-in template: your encounter card

Fill this in during session prep for each planned fight. Then you only have to type the rolled numbers at the table.

``` ENCOUNTER: ______________________ Party (always in): ______, ______, ______, ______ Foes (group by type): ______ x__, ______ x__ Display names for foes (spoiler-safe): ______________ Show initiative numbers? Yes / No Corner of screen: Top-left / Top-right Scene to switch to when combat starts: ______________ ```

Spoiler-safe names matter. If "Vampire Lord" appears on screen, viewers find out before the reveal. Use "Pale Stranger" until the players know.

Worked example

Say a four-player party meets goblins and their boss. Rolls come out as Aria 18, Borin 15, Goblins 12, Mira 9, Hooded Figure 7.

  • In the text-file method, you type those five lines in that order, put `>` on Aria and set `ROUND 1`. After Hooded Figure acts, move `>` back to Aria and change it to `ROUND 2`.
  • In a browser-source tracker that sorts automatically, you enter the names and numbers in any order. It puts them in order and marks the foes. In the Interact window you press a key or click to advance, and the round goes up when the order wraps back to the top.

If a goblin group dies off, take that line out between rounds, not partway through a turn.

Pre-session checklist

  • [ ] Tracker source is in your combat scene, positioned away from the webcam and map focus
  • [ ] Text is readable at 1080p. Check it in a recording or on your phone, not just the preview
  • [ ] Foe names are spoiler-safe
  • [ ] Browser source: "Refresh when scene becomes active" and "Shutdown when not visible" are unticked
  • [ ] Interact window (or text editor) is open on your second screen
  • [ ] You've done a test: advance through a full round and watch the round counter go up
  • [ ] Party HP display, if you use one, matches your current character sheets
  • [ ] Hotkey or scene ready to hide the tracker when combat ends

Common questions

Will a local HTML overlay slow my stream? A simple static page uses very little compared with games or VTTs. Pages with heavy animation use more, so watch OBS's stats panel during your test.

Can my players see it? Only on stream. If players at the table need it too, put the same page or text file in a window they can see.

Does it work offline? The text-file method always works offline. A browser source works offline only if the HTML file makes no web requests, so check this for any overlay you download.
